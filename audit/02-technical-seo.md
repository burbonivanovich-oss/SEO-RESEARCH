## 1. JavaScript-рендеринг: главная проблема

### Диагноз
Все 6 страниц являются SPA без Server-Side Rendering. Яндекс.Бот (и Googlebot в режиме «волны 1») индексируют страницы в два прохода:
- **Первый проход** — HTML без JS: видят скелет страницы
- **Второй проход** — JS-рендеринг: очередь, задержка до 2–3 недель

| Страница | Слов с JS | Слов без JS | Разрыв |
|---|---|---|---|
| /market | 1 242 | **8** | ×155 |
| /features | 906 | **5** | ×181 |
| /kkt | 2 167 | **47** | ×46 |
| /ofd | 1 409 | **12** | ×117 |
| /responses | 4 437 | **99** | ×45 |
| /gossistemy | 1 691 | **6** | ×282 |

### Подтверждение
- `<div id="app">` или аналог — контейнер SPA на всех страницах
- HTML-скелет: `<head>` + минимальная разметка + бандлы ~200–300 KB
- При запросе с UA `YandexBot` без JS: страница возвращает практически пустой `<body>`

### Решение
1. **SSR через Next.js/Nuxt.js** — полное решение, требует рефакторинга
2. **Prerender.io / собственный prerender** — промежуточное решение без рефакторинга кода, занимает 2–4 недели внедрения
3. **Минимальный SSR** — вынести в статический HTML: H1, первые 200 слов текста, meta-теги, структурированные данные

**Приоритет: максимальный.** Без SSR все остальные SEO-улучшения малоэффективны.

## 3. Canonical и редиректы

| URL | Финальный URL | Canonical | Совпадение |
|---|---|---|---|
| /market | /market | /market | ✅ |
| /market/features | /market/capabilities/roznitsa | /market/capabilities/roznitsa | ⚠️ Канон ≠ входящий URL |
| /market/kkt | /market/kkt | /market/kkt | ✅ |
| /market/ofd | /market/ofd-directoru | /market/ofd-directoru | ⚠️ Канон ≠ входящий URL |
| /market/responses | /market/responses | /market/responses | ✅ |
| /market/gossistemy | /market/gossistemy | /market/gossistemy | ✅ |

**Проблема /features и /ofd:**
Если внешние ресурсы, Яндекс.Вебмастер или внутренние перекрёстные ссылки используют URL `/market/features` и `/market/ofd`, PageRank передаётся через 301-редирект на другой URL. Canonical на финальном URL самоссылающийся — это правильно, но входящие URL теряют собственный «вес».

**Рекомендация:** Либо сделать `/market/features` контентным хабом (а не просто редиректом), либо явно задокументировать что `/market/features = /market/capabilities/roznitsa` и обновить все внутренние ссылки.

## 4. Schema Markup

### Текущее состояние

| Страница | Schema | Качество |
|---|---|---|
| /market | `<script type="ld+json">` **пустой** | ❌ JS-инъекция, не работает |
| /features | BreadcrumbList | ⚠️ Минимальный |
| /kkt | BreadcrumbList + FAQPage | ⚠️ FAQPage устарел (авг 2023) |
| /ofd | — | ❌ Отсутствует |
| /responses | — | ❌ Нет Review/AggregateRating |
| /gossistemy | — | ❌ Отсутствует |

**FAQPage ограничение (август 2023):** Google и Яндекс ограничили FAQ Rich Snippets только для государственных органов и медицинских организаций. Для коммерческих сайтов FAQPage в разметке не вредит, но rich snippet не отображается. Рекомендуется заменить на `Product` + `AggregateOffer`.

**Пустой schema-блок на /market:** тег присутствует в HTML, но `innerHTML` — пустая строка. Схема инжектируется через JS после загрузки бандла. При индексации без JS — schema не видна поисковику.

### Что нужно добавить

| Страница | Рекомендуемый тип |
|---|---|
| /market | Organization + WebSite + SiteLinksSearchBox |
| /features | BreadcrumbList + ItemList (возможности) |
| /kkt | Product + AggregateOffer + BreadcrumbList |
| /ofd | SoftwareApplication + Offer |
| /responses | AggregateRating + (выборочно) Review |
| /gossistemy | ItemList (ЕГАИС, Честный Знак, Меркурий) |

**Итого по сайту:** 501 изображение, ~74% без полезного alt текста.

### Критичные случаи
- `/market/kkt` — 91 изображение товаров каталога (кассы, сканеры, оборудование) — 80% без alt → Яндекс.Картинки не индексирует
- `/market/responses` — 136 аватаров и логотипов клиентов — 88% без alt → потеря всего раздела в Яндекс.Картинки

### Влияние на CWV
Незагруженные изображения (403) или медленно загружаемые без заданных размеров вызывают **CLS (Cumulative Layout Shift)** — прыжки контента при загрузке.
