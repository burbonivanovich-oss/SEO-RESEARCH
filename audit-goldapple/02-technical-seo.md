## 1. robots.txt — детальный разбор

### Базовые параметры
- **Размер:** 7,497 байт — детальный файл
- **Секций User-agent:** 45 (1 общая `*`, 1 для Googlebot, 43 заблокированных ботов)
- **Правил Disallow:** 192
- **Clean-param директив:** 47 (150 уникальных параметров)

### Критическая проблема: `Disallow: /*.html` — ложная тревога

Правило `Disallow: /*.html` присутствует в обоих разделах (`*` и `Googlebot`).  
**Это выглядит как критический баг, но фактически безвредно:**

Goldapple.ru **не использует `.html` суффикс** в URL. Sitemap подтверждает:
```
✅ /makijazh/nogti/lak-dlja-nogtej       (без .html)
✅ /19000044609-argabeta-5-fiber-shine-paste  (без .html)
✅ /f/bb-krem-korea                       (без .html)
```

**Вывод:** Это Magento 2 шаблонный robots.txt с правилом, не применяющимся к реальным URL. Безвредно, но создаёт путаницу и должно быть удалено для чистоты.

### Проблема: Googlebot `Disallow: /*?*`

```
User-agent: Googlebot
Disallow: /*?*
```

Это блокирует ВСЕ URL с параметрами для Googlebot. В теории нормально, если все важные фильтры реализованы как чистые URL (`/f/slug`). Но это также блокирует:
- Любые AMP-параметры
- Любые инструменты аналитики добавляющие параметры
- Потенциальные GET-параметры в инструментах разработчика

### Проблема: Заблокированы коммерческие разделы

Следующие разделы с коммерческим трафиком заблокированы для всех ботов:

| Path | Тип контента | SEO-потеря |
|---|---|---|
| `/sertifikaty` | Подарочные карты | Запросы «подарочный сертификат золотое яблоко» |
| `/reward-points` | Программа лояльности | Запросы «бонусы золотое яблоко» |
| `/private-sales` | Приватные распродажи | Запросы «скидки золотое яблоко» |
| `/all-products` | Все товары | Вспомогательная навигация |
| `/b2b/cards/receive/*` | B2B-раздел | B2B трафик |

### Позитив: Исключительно детальный Clean-param

47 Clean-param директив с 150 параметрами — один из самых детальных примеров в рунете.  
Правильно очищаются: UTM-параметры, AppsFlyer (`af_*`), Mindbox, Calltouch, Facebook (`fbclid`), Google Ads (`wbraid`, `gbraid`), партнёрские ID и другие.

```

Clean-param: af_adset_id&af_c_id&af_channel&af_click_lookback...
Clean-param: mindbox-click-id&rb_clickid
Clean-param: calltouch_tm&callibri
```

Это предотвращает дублирование URL с маркетинговыми параметрами в Яндекс-индексе.

## 2. Sitemap — детальный разбор

### Структура

```
/sitemap.xml (sitemap index)
├── /sitemap-1.xml  — 49,000 URL (категории + товары + /f/ + /s/)
├── /sitemap-2.xml  — 49,000 URL (только товары, priority 1.0)
├── /sitemap-3.xml  — 49,000 URL (только товары, priority 1.0)
├── /sitemap-4.xml  — ~49,000 URL (оценочно)
├── ...
└── /sitemap-10.xml — ~49,000 URL (оценочно)
Итого: ~490,000 URL
```

### Критическая проблема: Нет image sitemap

Sitemap объявляет namespace:
```xml
xmlns:image="http://www.google.com/schemas/sitemap-image/1.1"
```

Но ни в одном из 147,000 проанализированных URL **нет ни одного `<image:image>` тега**.

**Последствие:** Яндекс.Картинки и Google Images не получают структурированную информацию об изображениях товаров. Для beauty/косметика e-commerce это критично — визуальный поиск генерирует значительную долю трафика.

**Рекомендация:** Добавить image:loc для каждой товарной страницы:
```xml
<url>
  <loc>https://goldapple.ru/19000044609-argabeta-5-fiber-shine-paste</loc>
  <image:image>
    <image:loc>https://goldapple.ru/media/catalog/product/0/0/19000044609_main.jpg</image:loc>
    <image:title>Argabeta 5 Fiber Shine Paste</image:title>
  </image:image>
</url>
```

### Проблема: Однородные приоритеты

- Все товары: `priority 1.0` (максимум) — нет дифференциации
- Все категории: `priority 0.5`
- `changefreq: daily` для ВСЕХ 490,000 URL — технически неверно

**Рекомендация:** Дифференцировать приоритеты:
- Главная + ключевые категории: 1.0
- Популярные товары (по продажам): 0.9
- Обычные товары: 0.7
- Фильтры `/f/`: 0.6
- Архивные/сезонные: 0.3

### Проблема: Нет `<lastmod>` варьирования

Все 147,000 URL имеют одинаковый lastmod: `2026-04-25T21:00:10+00:00` — это время генерации sitemap, а не реального изменения страницы. Поисковики могут игнорировать lastmod при таком поведении.

## 3. WAF и Crawlability — главный риск

### Plaid Challenge Система

goldapple.ru использует проприетарную систему защиты «Plaid» (`serviceName: 'Plaid_Web_Frontend_GUN_Client'`):

```javascript
const apiCheck = () => {
  fetch('/web/api/v1/settings', {
    credentials: 'include',
    headers: {
      'plaid-platform': 'web',
      'plaid-version': '1.0.0',
      'plaid-store-id': 'ru',
    },
  }).then((res) => {
    if (res.ok) { location.reload() }     // ✅ Разрешено
    else { setTimeout(apiCheck, 10000) }  // ❌ Заблокировано
  });
};
```

**Механизм:** Каждый браузер делает запрос к `/web/api/v1/settings`. Сервер проверяет IP-репутацию, cookies, fingerprint. При отказе (403) — показывает challenge-страницу.

### Тест: Что видит бот

| User-Agent | Результат |
|---|---|
| Chrome 124 / Windows | ❌ Challenge (403 от API) |
| YandexBot 3.0 | ❌ Challenge (403 от API) |
| Простой curl / YandexBot UA | ✅ robots.txt, sitemap.xml |
| Playwright + Chrome UA | ❌ Challenge (Azure IP заблокирован) |

**Критический вопрос:** Заблокированы ли Yandex datacenter IPs?

goldapple.ru имеет значительный поисковый трафик (публичные данные), что говорит о том, что Яндекс-краулер не заблокирован на уровне IP. Вероятно, реальные Yandex crawler IPs из AS 202611 (Yandex LLC) внесены в whitelist WAF.

**Риск:** При любом изменении WAF-конфигурации или IP-диапазонов Яндекса — индексация может рухнуть без предупреждения.

### Рекомендация: Явный whitelist поисковых ботов

```nginx
# Добавить в WAF / nginx конфигурацию:
# Yandex crawler IPs (основные диапазоны)
allow 77.88.0.0/18;    # Yandex
allow 5.45.192.0/18;   # Yandex
allow 37.9.64.0/18;    # Yandex
# Google crawler IPs: https://developers.google.com/search/apis/ipranges/googlebot.json
```

## 4. URL-структура — сильная сторона

### Паттерны URL

| Тип | Паттерн | Пример | Оценка |
|---|---|---|---|
| Товар | `/SKU-slug` | `/19000044609-argabeta-5-fiber-shine-paste` | ✅ Отлично |
| Категория | `/category/subcategory/sub2` | `/makijazh/nogti/lak-dlja-nogtej` | ✅ Отлично |
| Фильтр | `/f/descriptive-slug` | `/f/bb-krem-korea` | ✅ Хорошо |
| Промо/бренд | `/s/brand-name` | `/s/la-roche-posay-anthelios` | ✅ Хорошо |

**Плюсы:**
- Без `.html` суффикса (нет дублирования)
- SKU в URL товара — уникальность без коллизий
- Транслитерация по-русски (`/makijazh`, `/uhod`) — читаемо для пользователей
- Логическая иерархия до 3+ уровней

**Потенциальная проблема:**
- SKU в начале URL (`/19000044609-...`) — поисковик видит числовой префикс. Некоторые рекомендуют ставить slug первым
- Длина slug: `argabeta-5-fiber-shine-paste` — хорошо, но некоторые могут быть очень длинными
